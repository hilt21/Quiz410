## 1. 结论

PRD 第 8 节目前是 JSON 示例，并非可执行的 JSON Schema。它能描述独立选择题，但缺少共享材料和连续子题的关系，表格只能塞进题干字符串。

建议 v1 使用 **三种答题类型 + 共享材料组 + 文本／表格内容块**。材料题是内容组织形式，不是第四种判题类型。200 题可以完整提取并表达，但当前内容不满足发布要求：第 1–160 题没有逐题解析。

本轮没有修改原题库、PRD 或 AGENTS.md；没有搭建 UI、答题引擎、生产题库或 CI。文档中的刷题建议和后续生成题库邀请均视为原文内容，未作为执行指令。

## 3. 候选数据契约

可执行文件：[question-bank-v1.schema.json](question-bank-v1.schema.json)，采用 JSON Schema Draft 2020-12。名称指整个主题文件；其中 `$defs.question` 定义单题。

| 层级 | 字段与约束 |
|---|---|
| 主题文件 | `schemaVersion: 1`、`topic`、`groups`（允许空数组）、`questions`（非空） |
| 单题 | 必填 `id`、`type`、`question`、`options`、`answer`、`explanation`、`source`；可选 `material` |
| 来源 | `source.file` 原文件名、`source.number` 原题号，支持逐题追溯 |
| 选项 | `id` 与 `text` 非空；ID 在题内唯一；展示顺序由数组决定 |
| 答案 | 选项 ID 数组、无重复；单选／判断恰好 1 个，多选至少 2 个；按集合比较，不要求用户选择顺序 |
| 材料组 | `id`、`title`、`material`、有序 `questionIds`；一题最多属于一个组 |
| 文本块 | `{ "type": "text", "text": "原文" }` |
| 表格块 | `{ "type": "table", "headers": ["温度/℃", "溶解时间/s"], "rows": [["20", "80"]] }`；行列数一致 |

每层拒绝未知字段。文本按纯文本处理，不承载 HTML 或隐藏 Markdown 协议。表格单元格用字符串，保留单位、范围、沉浮状态和原始精度；不是统计计算数据模型。暂不支持合并单元格、图表渲染或公式。

材料块按数组顺序阅读。先读取共享材料，再读取单题材料与题干。完整练习按材料组抽取，组内保持原题顺序；错题练习可选取组内部分题，但必须加载完整共享材料。每个子题独立记录进度，不把材料组计作额外题目。选项顺序先保留原文，尤其 171 题的选项内容本身含 A/B/C 方案名称。

### 相对 PRD 的待确认调整

- 把主题归属提升到主题文件，避免每题重复 `topic`。本次 `science-training` 仅为验证用集合 ID，尚未建立正式主题 manifest 或逐题知识分类。
- 增加 `groups`、单题可选 `material` 和表格块，避免复制同一材料五次。
- 暂不纳入 `image`；PRD 的图片要求仍需真实图片、替代文本和资源路径样本验证后协调修改。
- 暂不纳入 `difficulty`、`tags`：原题没有逐题标注，不自动猜测；若要求 v1 保留，需先确定标注标准。
- 将 `source: null` 改为可追溯来源对象；判断答案统一转为字符串 ID，避免混合布尔值与选项字母。

## 4. 校验执行与结果

完整映射：[real-bank.draft.json](real-bank.draft.json)，包含 200 道原题、原选项、答案和 8 份原始共享材料；判断选项为规范化生成，√／× 转成 `true`／`false`，A–D 转成小写 ID。保留原题号，不补造解析、难度或科学结论。

表格样本：[table-101.fixture.json](table-101.fixture.json)，将第 101 题的四对真实数据转写成两列表格。全量映射保留原文叙述；没有自动将所有材料改写为表格。

使用临时环境中的 Python `jsonschema` / `Draft202012Validator` 完成校验，明细见 [validation-results.json](validation-results.json)。临时提取与断言脚本不加入应用仓库。

JSON Schema 负责字段、类型与基数；跨题 ID 唯一、答案引用、材料引用和表格宽度由本次额外断言检查。正式 manifest 尚不存在，未验证主题注册；没有图片样本，未验证资源存在性。结构通过不等于全部科学答案已通过学科审校。

可重新执行严格校验（需已安装 `jsonschema`，在仓库根目录运行）：

```sh
python3 - <<'PY'
import json
from pathlib import Path
from jsonschema import Draft202012Validator
p = Path('docs/schema-validation')
schema = json.loads((p / 'question-bank-v1.schema.json').read_text())
bank = json.loads((p / 'real-bank.draft.json').read_text())
Draft202012Validator.check_schema(schema)
errors = list(Draft202012Validator(schema).iter_errors(bank))
for error in errors:
    print(list(error.absolute_path), error.message)
print(f'{len(errors)} errors')
raise SystemExit(bool(errors))
PY
```

当前预期输出 160 条错误并非零退出，表示发布阻断；该命令只复验严格 Schema，不重跑本轮的语义断言和反例。

## 5. 内容问题与确认边界

1. **发布阻断：** 为 1–160 题补充经审阅的逐题解析；主题级说明不能冒充单题解析。
2. **内容待审：** 172 题问三种飞机中“哪种最稳定”，但材料未给 A 的重复测量数据。现有 B 答案无法排除 A 更稳定；建议后续限定为 B/C 比较或补齐 A 数据。本轮保留原文与答案，未擅自修题。
3. **质量待审：** 情境解析多为通用原则，结构完整不代表解释充分；后续逐题审阅时再判断。
4. **确认事项：** 是否采用本稿的共享材料组、文本／表格块、按组抽题规则，以及暂缓图片／步骤结构和难度／标签字段的范围。
